Four Power BI projects from a fictional manufacturing company: **shop-floor monitoring**,
**commercial analytics**, **procurement** and **product portfolio**. These are the
structures of production reports that run on ERP data — republished here with
**fully synthetic data**.

> **Test Firma A.Ş.** is a fictional company. Every customer, supplier, order,
> price and production record in this repository is generated by `tools/veri_uret.py`;
> none of it comes from a real business. The factory floor plans are invented too.

Report labels are in Turkish, matching the original. Each page is explained in English
below and in the per-project READMEs.

## Opening the reports

Everything is in **Power BI Project (`.pbip`)** format: the model is `model.bim` (TMSL) and
the report is `report.json` — plain text, so it is readable and diffable in version control.

```bash
git clone https://github.com/Secure-Sentinel/powerbi-portfolio.git
```

1. Open the `.pbip` file inside a project folder with Power BI Desktop
   (2.130+ · if needed enable *File → Options → Preview features → Power BI Project (.pbip)
   save option*).
2. Hit **Refresh**. Data is read from the `VeriKaynagi` ("data source") parameter, which
   defaults to the GitHub raw URL of this repository's `data/` folder.
3. To work offline, point `VeriKaynagi` at your local clone instead, e.g.
   `C:\repo\01-scada-uretim-izleme\data`.

Regenerate the data yourself:

```bash
python tools/veri_uret.py --bugun 2026-07-30
```

The same `--bugun` (today) and `--olcek` (scale) always produce byte-identical output —
the seed is fixed. The date matters: several measures are `TODAY()`-relative, so the data
is positioned around whatever "today" you pass.

Before opening the `.pbip` files you can check that the repository is internally consistent
— CSV headers against model columns, relationship and sort-by references, table names inside
DAX, and every field reference in the report:

```bash
python tools/dogrula.py
```

## Where the data comes from in real life

The original reports are fed by SQL views over an ERP database: sales and invoice
movements, customer balances, work-order tracking and machine activity logs. Power BI runs
in **import** mode and refreshes several times a day; the SCADA report loops on shop-floor
screens with auto-refresh.

In this repository that layer is split in two:

- **[`sql/`](sql/)** — a simplified, readable SQL equivalent of the tables each report consumes.
  It is not the production view logic; it shows the shape and the joins.
- **`data/` + `tools/veri_uret.py`** — synthetic data filling that same schema.

Everything on the model side (table and column names, DAX measures, calculated columns,
relationships, format strings, auto date hierarchies) is transcribed one-to-one from the
originals.

## Technical notes

- **Model culture is `tr-TR`.** Some DAX relies on Turkish-culture name resolution
  (e.g. `[Yıl]` resolving to `[YIL]`), so the culture must not be changed.
- **Auto date/time is on.** A few visuals use auto date hierarchies; the corresponding
  `LocalDateTable_*` tables are defined explicitly in the model.
- **Built-in visuals only** — no custom visuals, so the files open on any Power BI Desktop
  installation.
- CSVs are UTF-8, comma separated, `.` decimal separator, typed on the M side with the
  `"en-US"` culture.
